# 기기 간 동기화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 아이폰과 PC에서 같은 단어·학습 기록·오늘 배정·설정을 보도록, 로그인 없이 동기화 코드로 Supabase를 통해 동기화한다.

**Architecture:** 기기 안은 지금 Dexie 구조(숫자 id)를 유지하고, 모든 레코드에 `modifiedAt`을 훅으로 자동 기록한다. 동기화 경계(`records.ts`)에서만 숫자 id ↔ 단어 키로 바꿔 Supabase `records` 테이블과 `pull`/`push` RPC로 주고받는다. 스케줄러가 앱 시작·화면 복귀·online·로컬 변경 시점에 엔진을 한 번에 하나씩 실행한다.

**Tech Stack:** Vite 8 + React 19 + TypeScript, Dexie 4, Supabase(Postgres RPC, `fetch`로 호출), vitest 4 + fake-indexeddb 6(개발용)

**Spec:** `docs/superpowers/specs/2026-10-29-sync-design.md`

## Global Constraints

- 런타임 의존성 추가 없음. 개발 의존성만 `vitest@^4.1.12`, `fake-indexeddb@^6.2.6` (vitest 5는 Node 22.12+ 필요, 로컬은 Node 20이라 4.x 사용)
- 단어 키: `wordKey(word, reading) = JSON.stringify([word, reading])` — `\u0000` 금지(Postgres 텍스트가 거부)
- 충돌: 레코드별 `modifiedAt`이 큰 쪽(같으면 기존 유지). 예외: daily는 진행량 우선(Task 5)
- 받기 1000개씩, 보내기 500개씩. 로컬 변경 후 3000ms 디바운스
- 동기화 코드: 16바이트 무작위 → Crockford Base32 26자(`0123456789ABCDEFGHJKMNPQRSTVWXYZ`)
- 환경 변수 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. 없으면 동기화 기능 전체 비활성, 앱은 그대로 동작
- UI 문구는 한국어, 스타일은 기존 CSS Modules·CSS 변수 재사용, 코드 주석은 한국어로 기존 밀도에 맞춤
- 동기화 실패는 학습 흐름을 막지 않는다
- 모든 테스트: `npm test` (vitest run)

## Review Focus

1. 두 번째 기기가 받기 전에 학습 화면을 열어 빈 오늘 배정이 생겨도, 다른 기기에서 진행한 오늘 배정이 덮이면 안 된다 → Task 5 `daily: 진행량 많은 쪽 우선`, Task 6 `second device opens study before first pull`
2. 단어 키에 `\u0000`이 들어가면 서버 저장이 실패한다 → Task 2 `wordKey has no NUL`
3. 처음 연결 시 수천 개 업로드 중 중간 배치가 실패하면 다음 시도에서 빠짐없이 다시 보내야 한다 → Task 6 `push failure mid-batch retries everything`
4. 받기 도중 네트워크가 끊기면 아무것도 적용되지 않고 `lastSeq`도 그대로여야 한다 → Task 6 `pull failure applies nothing`
5. 코드를 소문자·하이픈·공백·O/I 혼동으로 입력해도 연결되고, 틀린 코드는 상태를 저장하지 않아야 한다 → Task 3 `normalizeCode`, Task 6 `joinCode with bad code saves nothing`

- [ ] **Step 1: `supabase/schema.sql` 작성**

```sql
create table if not exists records (
  sync_code text not null, kind text not null check (kind in ('word','progress','daily','settings')),
  key text not null, data jsonb, deleted boolean not null default false,
  modified_at bigint not null, seq bigint not null,
  primary key (sync_code, kind, key)
);
create sequence if not exists records_seq;
create index if not exists records_code_seq on records (sync_code, seq);
alter table records enable row level security;
revoke all on records from anon, authenticated;

create or replace function check_code(p_code text) returns void language plpgsql as $$
begin
  if p_code is null or p_code !~ '^[0-9A-HJKMNP-TV-Z]{26}$' then raise exception 'bad_code'; end if;
end $$;

create or replace function pull(p_code text, p_after_seq bigint, p_max int)
returns table (kind text, key text, data jsonb, deleted boolean, modified_at bigint, seq bigint)
language plpgsql security definer set search_path = public as $$
begin
  perform check_code(p_code);
  return query select r.kind, r.key, r.data, r.deleted, r.modified_at, r.seq from records r
    where r.sync_code = p_code and r.seq > p_after_seq order by r.seq limit least(p_max, 1000);
end $$;

create or replace function push(p_code text, p_items jsonb) returns void
language plpgsql security definer set search_path = public as $$
begin
  perform check_code(p_code);
  perform pg_advisory_xact_lock(hashtext(p_code));
  insert into records as r (sync_code, kind, key, data, deleted, modified_at, seq)
  select p_code, i->>'kind', i->>'key', i->'data', coalesce((i->>'deleted')::boolean, false),
         (i->>'modified_at')::bigint, nextval('records_seq')
  from jsonb_array_elements(p_items) i
  on conflict (sync_code, kind, key) do update
    set data = excluded.data, deleted = excluded.deleted, modified_at = excluded.modified_at, seq = excluded.seq
    where excluded.modified_at > r.modified_at;
end $$;

revoke all on function pull(text, bigint, int), push(text, jsonb), check_code(text) from public;
grant execute on function pull(text, bigint, int), push(text, jsonb) to anon;
```
끝에 주석으로 확인 쿼리: 같은 키를 modified_at 2 → 1 순서로 push하면 2가 남는지, pull의 seq가 증가하는지, 잘못된 코드에 `bad_code` 오류가 나는지. (한 push 안에 같은 키가 두 번 있으면 `on conflict`가 오류를 내므로 클라이언트는 키별로 하나만 보낸다 — Task 5 `collectChanges`가 보장)
